# CLAUDE.md

Guidance for an AI assistant (Claude Code or similar) working in this repository.

## What this repo is

A bootstrap kit for engineers new to CATIA V5 at a company that keeps large assemblies.
Users are not CATIA experts. Keep answers short, task-oriented, and expressed as concrete
menu paths, toolbar names, or runnable macro code. Never assume the user knows a workbench name.

## Read these first, in order, if they exist

1. `local/index/INDEX.md` then the other files in `local/index/`. These describe the user's
   actual CATIA release, install path, and the company's own macros, standards, templates, and
   settings. They are generated by `tools/hookup.py index`. If they are missing, say so once
   and suggest running the hookup, then continue with the generic material.
2. `company/*.md`. Company conventions, PLM workflow, licensed workbenches, who to ask.
3. `local/chm/INDEX.md` if present. That is the extracted official V5 automation reference.
   Prefer it over memory for any API signature question.
4. `docs-index/automation-object-model.md`. The curated map of the automation API.

## Rules

- **Reuse before writing.** When asked for a macro, search `local/index/macros.md` for an
  existing company macro that does the job. Point to it by path. Only write new code when
  nothing fits, and say which existing macro is closest.
- **Follow company conventions** in `company/conventions.md` for naming, units, part numbering,
  and where macros may be saved. If the file is still the unfilled template, say so.
- **Never modify files under the indexed roots** (macro shares, template libraries, standards).
  New macros go in `macros/scratch/` unless the user says otherwise.
- **Never change CATIA settings for the user.** Give the Tools > Options path and the value.
- **Large assemblies are the default assumption.** When suggesting an action, consider whether
  it forces a full load into Design Mode and warn when it does. Prefer Visualization Mode,
  selective load, and Search over expanding the whole tree.
- **Version-sensitive claims get a hedge.** Menu paths and API members shift between releases.
  When the release is known from `local/index/environment.md`, state answers for that release.
  When it is not known, say "verify in your release" once, not on every line.
- **CATScript by default, CATVBA when the user asks for it or needs forms and IntelliSense.**
  Python via `pycatia` only when the user has Python on the CATIA machine.
- **Macro code must** start with `Language="VBSCRIPT"` (CATScript), define `Sub CATMain()`,
  check `CATIA.ActiveDocument` type before casting, and use `On Error` handling per
  `macros/templates/`. Keep macros read-only against the model unless the user asked for edits.
- Do not copy model files, CHM contents, or company documents into this repository. Indexes
  hold paths and short summaries only.

## Where things live

| Path | Purpose |
|---|---|
| `quickref/` | Task cards. Edit these when the user corrects a menu path for their release. |
| `macros/templates/` | Skeletons to copy. `macros/examples/` are small working macros. |
| `macros/scratch/` | User's sandbox. Git-ignored. |
| `tools/hookup.py` | `init`, `index`, `doctor`. `tools/extract_chm.py` extracts the API reference. |
| `local/` | Git-ignored per-user config and generated indexes. |
| `company/` | Company-specific facts. Meant to be filled in and committed in an internal fork. |
| `ai/prompts.md` | Starter prompts users can paste. |

## When the user is stuck in CATIA

Ask for three things before anything else: which workbench is active (top-right icon),
what the spec tree shows selected, and whether the product is in Design or Visualization mode.
Most new-user problems are one of those three.
